# DB 재설계 전환 후 실기기 스모크 절차

운영 DB 가 baseline(20261010000000)으로 바뀐 뒤, db-redesign 브랜치 앱을 dev-client 로 운영 DB 에 붙여
확인한다. 모두 통과하면 EAS 빌드 → alpha 제출로 넘어간다(운영자 승인 아래).

## 준비

1. `git checkout db-redesign` 후 `npm install`.
2. `.env` 의 `EXPO_PUBLIC_SUPABASE_URL` · `EXPO_PUBLIC_SUPABASE_ANON_KEY` 가 운영 프로젝트
   (gvoedaagemotwuzmfxfe)인지 확인한다.
3. 기기를 USB 로 연결하고 `adb reverse tcp:8081 tcp:8081` → `npx expo start --dev-client`.
   기존 dev-client 앱이 깔려 있으면 그대로 쓴다(네이티브 변경 없음).
4. 이전 DB 의 세션 토큰이 남아 있을 수 있다. 앱 데이터를 지우거나, 첫 실행에 "로그인이 만료되었습니다"
   안내 후 로그인 화면으로 가면 정상이다.
5. **새 매니저 웹(db-redesign) 이 배포된 뒤에야** 할 수 있는 항목은 ⓜ 로 표시했다
   (임시 비밀번호 계정 · 방문 기록 · 스탬프 · 쿠폰 · 투표 만들기).
6. 쿠폰 사용 비밀번호는 운영자가 교체한 새 값으로 한다.

## dev-client 로 확인할 수 없는 것: 운세 광고 재뽑기

dev 빌드(`__DEV__`)는 Google 공용 테스트 광고 단위를 쓴다(`src/services/rewardedAdService.js`).
테스트 단위는 우리 AdMob 단위가 아니어서 admob-ssv 콜백을 부르지 않는다. 그래서 dev-client 에서
재뽑기를 누르면 광고는 나오지만 서버 확인이 오지 않아 "광고 확인 지연" 안내에서 멈춘다.
**이것은 정상이다.**

재뽑기는 EAS 로 만든 alpha 빌드(실제 단위 daily-fortune-redraw)에서 확인한다.

- 확인 전에 테스트 기기를 AdMob 테스트 기기로 등록한다. 자기 광고를 실제로 보면 무효 트래픽이 된다.
- 첫 뽑기 후 재뽑기 → 광고 끝까지 시청 → 새 카드가 나오면 통과.
- 실패하면 Supabase 대시보드 → Edge Functions → admob-ssv 로그에서 콜백이 왔는지 본다.

## 통과 후

- EAS production 빌드 → `eas submit` 로 alpha 트랙 제출(운영자 승인 후).
- alpha 빌드에서 재뽑기를 확인하고, 1·3·5번을 짧게 다시 본다.
